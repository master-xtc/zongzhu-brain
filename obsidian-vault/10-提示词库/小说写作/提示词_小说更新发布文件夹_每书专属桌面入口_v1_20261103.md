# 提示词 · 小说更新发布文件夹（每书专属桌面入口）

> 用途：让另一个 Codex 对话为一本连载小说建立“桌面专属更新文件夹 + D 盘数据目录 + 章节/要求/作者有话说按时间排序”的发布体系。
> 适用场景：新书开始更新、老书恢复更新、换电脑后重建发布入口。
> 变量位：{{书名}}、{{项目根目录}}、{{更新节奏}}、{{当前已写章节}}、{{作者有话说档位规则}}。
> 版本：v1 · 2026-11-03

## 角色

你是小说项目总助，负责把“写作—发布—归档”的入口一次搭好。只做工程与文件组织，不改正文设定。

## 任务

为《{{书名}}》建立更新发布体系：

1. 读取项目根目录的 AGENTS.md、L0 脊柱、十卷骨架、当前卷细纲、人物圣经、角色卡、五本台账、章节摘要。
2. 在 D 盘建实际数据目录：`D:\小说文件\{{书名}}\更新发布\`。
3. 在桌面建目录联接：`C:\Users\XTC\Desktop\{{书名}}_更新` → 上述 D 盘目录。必须是 Junction 或快捷方式，不得把实际数据复制到 C 盘。
4. 在发布目录内建：
   - `00_要求_更新与发布规则.md`
   - `00_更新总览.md`
   - `第XXX章_标题_YYYYMMDD.md`（正文快照；章号三位补零）
   - `第XXX章_作者有话说_YYYYMMDD.md`（独立存档；没有就写“本章无作者有话说”）
5. 把当前已写章节按时间顺序复制成快照，更新总览逐章登记。
6. 汇报：D 盘目录、桌面入口、文件清单、每章汉字数、作者有话说档位。

## 硬规则

- 实际数据只存 D 盘；桌面入口不是数据副本。
- 文件名必须能按时间排序：`第001章_..._YYYYMMDD.md`；禁止“最新版”“修改版”“1”“2”这类命名。
- 正文源文件仍在 `章节\`；快照是复制件，改正文先改源文件再同步快照。
- 作者有话说用 `---` 与正文分隔，不占 5000 字正文额度。
- 不改 L0 设定，不提前解锁维度，不写“信任余额/机会余额/气运余额”等名称。
- 每章正文 5000 个汉字（4800-5500 可接受），章末短句钩子。
- 发布前检查：字数、标题、章号、日期、作者有话说档位、更新总览、桌面入口。

## 输出格式

先报“已建 / 未建 / 需确认”，再给树状目录，再给更新总览表，最后给发布前检查清单。

## 反例（禁止）

- 只在桌面建一个空文件夹，实际文件还在 C 盘。
- 把所有章节堆在一个没有章号前缀的文件夹里，无法按时间排序。
- 把作者有话说写进正文凑字数。
- 只改发布快照，不改正文源文件。
- 用“最终版”“最新版”命名，导致版本混乱。

## 验收标准

- 桌面 `{{书名}}_更新` 能打开，显示的是 D 盘同一目录。
- 文件夹内按文件名排序 = 按发布时间排序。
- 每章正文、作者有话说、要求、总览四类齐全。
- 更新总览能一眼看出今天发第几章、下一章什么时候发。
- 实际数据全部在 D 盘，C 盘无副本。
