# 提示词_VibeCoding三端打包发布_v1

## 一、名称
VibeCoding 三端打包发布 · 全流程指挥提示词（安卓 / iOS / 小程序）

## 二、用途
- 用一段结构化的"任务说明书"，让 AI 辅助完成 AI 编程项目的三端打包发布：安卓 APK 云打包+应用市场上架、iOS IPA 签名+App Store 上架、微信小程序上传+审核+发布
- 覆盖最关键的决策点：三端先上哪一端、上架前六样材料、签名/备案/审核的坑
- 既可直接投喂 AI 编程工具（HBuilderX 配合 AI），也可作为给下属 AI 的执行任务书

## 三、适用场景
- uni-app / 小程序 / APP 项目开发完成，准备打包发布时
- 不确定三端优先级、不知道要准备哪些账号和材料时
- 打包失败、审核被拒、证书/备案/包名配置出错时，用本提示词让 AI 给出排查清单
- 需要把发布经验沉淀给团队或下属复用

## 四、变量位
| 变量 | 含义 | 示例值 |
|---|---|---|
| 【项目类型】 | 技术栈与工程形态 | uni-app 论坛项目 |
| 【目标平台】 | 本次要上哪一端 | 微信小程序（优先）/ 安卓 / iOS |
| 【应用名称】 | 各平台展示名 | 某某开源论坛 |
| 【包名/BundleID】 | Android 包名与 iOS Bundle ID | com.example.forum |
| 【主要功能】 | 用于分类/简介/审核材料 | 发帖、评论、点赞、登录 |
| 【用户场景】 | 判断三端优先级 | 用户靠微信分享进入 |
| 【已有材料】 | 已准备的账号/证书/备案 | 有安卓发布证书、无苹果账号 |
| 【合规风险】 | 业务涉及 UGC/支付/登录 | 有用户发帖评论（UGC） |

## 五、正文模板（任务说明书，200 字以上）
我正在用【项目类型】做一个产品，主要功能是【主要功能】，目标用户的使用场景是【用户场景】。请以资深移动端发布顾问身份，帮我完成三端打包发布规划与执行指导。

第一步，先判断三端优先级：快速验证+微信生态优先小程序；国内安卓用户为主优先安卓；覆盖苹果用户才做 iOS。当前我【已有材料】，所以建议先上【目标平台】，理由是【结论】。

第二步，给我上架前六样材料检查清单：应用名称/包名、发布证书归档、主体认证与备案、隐私政策与权限说明、应用图标、审核测试账号。逐项标注我现在缺什么、怎么补、大概成本。

第三步，按目标平台给出分步操作：安卓（真机调试→云打包 APK→市场发布，注意包名与 APK 一致）；iOS（AppID→发布证书→描述文件→P12→云打包 IPA→App Store Connect 上传审核，注意 2026 年需满足最新 SDK 要求）；小程序（真实 APPID→上传→版本管理→提交审核→发布）。每一步给出操作入口、要填的关键字段、常见报错与解决。

第四步，列出我的业务（含【合规风险】）最可能被拒的审核项和规避方法；最后给我一份"先跑通哪一端、再复制到另一端"的发布排期建议。全程用大白话，先给结论再展开。

## 六、变体
1. 精简版（快模型）：一句话决策 + 六样材料清单 + 目标平台 3 步流程，每步一条命令/入口
2. 报错排查版：追加「当前报错：【报错内容】+ 截图描述」，AI 只给原因、验证方法和修复步骤
3. 材料代办版：输出可勾选清单「名称/证书/备案/隐私/图标/测试账号」+ 每项办理入口与耗时
4. 排期版：要求输出三端发布排期表（周计划），先小程序验证 → 安卓 → iOS
5. 下属执行版：结尾追加「执行人按本任务书逐步完成，每步回报产物路径与截图；关键材料（证书/密码/API Key）只存本地环境，不写入任何文档」

## 七、验收标准
- 输出包含三端优先级结论、六样材料清单、目标平台分步操作、审核风险清单四项，缺一算不合格
- 安卓/ iOS / 小程序的每步都有入口、关键字段和验证方法
- 涉及证书、密码、API Key 的操作只指示本地存储，不要求写进任何文本
- 无虚假审核时限承诺（审核时间只作参考，以后台为准）；命名符合规范
