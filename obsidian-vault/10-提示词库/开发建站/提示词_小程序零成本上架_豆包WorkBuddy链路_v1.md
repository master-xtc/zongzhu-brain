# 提示词_小程序零成本上架_豆包WorkBuddy链路_v1

## 名称
小程序零成本 1 小时上架（豆包 + 腾讯 WorkBuddy + 微信开发者工具）

## 用途
指导零基础用户（个人/副业）用免费工具完成"产品想法 → 上线微信小程序"全流程：需求梳理、AI 出码、调试、备案、发布；并明确个人主体的变现边界（广告流量主可，内付费不可）。

## 适用场景
- 习总或客户想快速做一个小程序验证想法（工具/效率/记录/查询类）；
- FIT COMMAND 健身指挥台转小程序 MVP；
- 接单时给客户演示"低成本小程序交付"流程；
- 个人副业做小程序占坑/引流/广告变现。

## 变量位
- {产品想法}：要做什么小程序（可让豆包推荐，建议自带想法更省积分）
- {需求文档}：豆包导出的 PRD 文件路径
- {本地工作空间}：放代码的本地文件夹（建议用产品名命名）
- {小程序名称/AppID}：微信公众平台注册后获取

## 正文模板（步骤化指令，可直接下发或自用）

1. **需求梳理（豆包，免费）**：与豆包充分聊天明确产品定位、目标人群、核心功能与产品边界（"不是商城、不是社区"），形成 PRD 文档导出备用。目的：把需求讨论放在免费环节，省 WorkBuddy 积分。
2. **代码开发（腾讯 WorkBuddy，免费积分）**：下载客户端 → 新建任务选"代码开发" → 选择本地工作空间（用产品名建文件夹）→ 召唤内置"软件开发团队"（交付总监/产品经理/架构师/工程师/QA）→ 上传 PRD + 附指令："请按我的产品规划，帮我开发小程序产品" → 发送执行，等待生成代码。积分不够可签到/会员/切换其他模型 API。UI 有更高要求时先用设计原型专家团出页面设计再交开发团队。
3. **调试（微信开发者工具，免费）**：导入生成的源码文件夹 → AppID 填注册的小程序 ID（不发布可用测试号）→ 后端服务选微信云开发 → 创建后调试 → 二维码预览 → 有问题回到 WorkBuddy 反馈（附报错截图）修复 → 重编验证。
4. **上架**：调试通过 → 上传代码 → 公众平台提交审核 → 完成小程序备案（个人主体=身份证+人脸核身，无营业执照要求；备案是上线最慢环节，按 1-4 周预算）→ 审核通过发布。
5. **变现决策（写代码前就想好）**：
   - 个人主体（免费/30 元认证）：广告流量主（开屏/插屏/激励视频）→ 可做；
   - 内付费/虚拟支付（卖课/会员/AI 功能）→ 必须企业认证 → 提前升级个体户（认证 30 元/年）或企业。

## 变体
- 变体 A（纯自用/体验）：不发布，一直用体验版，跳过备案；
- 变体 B（SaaS 模板建店）：不需要复杂功能/要前台后台 → 用 SaaS 工具（如 SaaS哥类模板平台）上千套模板拖拽建店，商业功能仍须企业/个体户主体；
- 变体 C（传统路线对照）：GPT 手写 WXML/WXSS/JS 三件套（适合要完全掌控代码的场景）。

## 验收标准
- 产物：可在微信开发者工具正常编译运行的小程序源码；已注册小程序并拿到 AppID；
- 流程：从想法到提交备案 < 1 小时（实测基准，不含备案审核等待）；
- 合规：个人主体不做 UGC/社交/医疗/金融类目；不碰支付；文案无"诊断/治疗/医嘱"类表述；
- 文档：PRD、源码、审核/备案账号信息齐全，命名规范。

## 反例规避
- 不要在 WorkBuddy 里长篇聊需求（烧积分），需求讨论放豆包；
- 不要一上来就让 AI 塞购物车/社区/排行榜等多余功能（PRD 明确边界）；
- 不要默认 AI 生成的 emoji/AI 味 UI 直接上架（个人主体也影响通过率与体验）；
- 不要忘记变现规划：做完才发现个人主体开不了支付 = 烂尾重灾区。
