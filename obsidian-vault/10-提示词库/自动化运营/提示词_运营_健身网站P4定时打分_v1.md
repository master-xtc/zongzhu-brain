# 提示词_运营_健身网站P4定时打分_v1

> 分类：自动化运营 / 开发建站（健身指挥台 P4 阶段专用）

## 八字段
1. **名称**：提示词_运营_健身网站P4定时打分_v1
2. **用途**：让任意 AI（总助 Codex / Hermes / 新会话）落地"健身指挥台"每日定时打分系统——每天定时汇总训练、饮食、体态三域完成度，生成打分与次日提醒
3. **适用场景**：健身网站 P4 阶段开工；P3 手机适配已闭环后接续；要求本地优先、数据不出站
4. **变量位**：
   - `{SITE_DIR}`：网站本地根目录（默认 `D:\健身教练\网站`）
   - `{DATA_STORE}`：打分与打卡数据存储位置（默认本地 `D:\健身教练\data`，禁止 C 盘/服务器）
   - `{SCORE_TIME}`：每日定时触发时间（默认 21:00）
   - `{NOTIFY_CHANNEL}`：提醒通道（Notification API 浏览器推送 / Hermes cron / 文件落盘三选一，默认文件+浏览器）
   - `{WEIGHTS}`：打分权重（默认 训练40 饮食40 体态20，可调）
5. **正文模板**（新会话开场直接粘贴，已按要素补全）：

你是"健身指挥台"网站的技术总助，负责 P4 阶段：每日定时打分系统。目标：每天 `{SCORE_TIME}` 自动汇总当日训练打卡、饮食热量卡、体态记录三域数据，按权重 `{WEIGHTS}` 生成 0-100 完成度打分，输出打分卡并给出次日 1-3 条提醒；全程本地优先，数据存 `{DATA_STORE}`，不依赖服务器与第三方云。受众是习总本人，风格必须清单化、务实、无情绪化表述；结构为：数据读取 → 三域完成度计算 → 加权总分 → 打分卡文本 → 提醒清单 → 落盘/推送。打分卡必须包含：日期、三域各自百分比、总分、一句结论、明日 3 条可执行提醒；示例：训练 80% 饮食 60% 体态 50% → 总分 66，提醒"晚餐补蛋白、明早空腹称重、完成背部日计划"。红线：不存照片到服务器/Blobs、API Key 只存本地 .env、不用 emoji、不伪造数据（无数据域标注"未记录"不硬凑分）；验收标准：定时任务真实触发、打分可查可回溯、提醒通道可达，连续 3 天运行无故障即算通过。开工前先读 `D:\健身教练\报告\_健身网站P3适配测试_20260821.md` 与 `D:\健身教练\改动记录\_健身网站P2卡通展板_20260821.md` 恢复上下文，先产出方案再编码，每阶段落盘并建议开新会话。

6. **变体**：
   - v1a 浏览器通知版：本地 JS + Notification API，页面打开时请求权限，定时触发（页面需常开）
   - v1b Hermes cron 版：Hermes 定时任务生成打分卡 md 落盘 + 平台推送（无需页面常开，推荐）
   - v1c 纯落盘版：无推送，仅每日生成 `打分卡_YYYYMMDD.md` 存档，成本最低
7. **验收标准**：定时触发真实发生；打分算法与权重一致；无数据域如实标注；提醒通道可达；全部产出在 D 盘、无 emoji、无密钥外泄；配套复盘入 growth
8. **使用记录**：2026-08-21 创建（P3 闭环后、P4 开工前）；首次使用建议选 v1b Hermes cron 版（成本约 0 元，仅本地）

## 反例规避
- 不做云函数打分（数据上云，违反本地优先）
- 不接短信/付费推送（成本高，Notification/Hermes 免费够用）
- 不把打分做进聊天流而不落盘（第十六章铁律：关键产出立即落盘）
