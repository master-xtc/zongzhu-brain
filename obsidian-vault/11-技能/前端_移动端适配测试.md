# 前端_移动端适配测试

## 技能名
移动端多视口适配测试与视觉核对（含贴纸/网格类布局）

## 触发场景
- 网站/网页上线前做手机适配回归（360/390/430 三视口全流程测试）
- 网格类布局（贴纸库、卡片墙）行数列数验收
- 底部固定导航遮挡内容排查
- 动画元素在截图/适配中破版的核查

## 步骤
1. 锁定视口清单（360/390/430），逐视口逐页建立基线：scrollWidth vs clientWidth、元素边界、控制台错误
2. 截图前注入 `* { animation-play-state: paused !important; }` 暂停动画，避免动效干扰
3. 截图必须标注真实滚动位置（scrollTo 顶部/指定锚点 + 等 Lenis 平滑滚动完成，不能只等 setTimeout）
4. 视觉核对走多模态直连通道（ARK/豆包），像素方差自检防"全同图假通过"
5. 网格验收：`repeat(N, minmax(0, 1fr))` 防内容撑破；360/390 三列、430 四列视设计定
6. 底部 tabbar 遮挡：DOM 实测元素 bottom 与滚动距离对比，不能只信 fullPage 截图

## 关键经验（踩坑实录）
- fullPage 截图拼接假象：固定定位元素（tabbar）在拼接处会"重复出现/遮挡"，像素抽条即假象，必须用 DOM 实测证伪，不得据此判 FAIL
- grid 子项 `minmax(0,1fr)` 是防内容撑破行数的关键；只用 `1fr` 会被长内容撑宽导致列数错误
- Lenis 平滑滚动会劫持 scrollTo：`scrollTo(0,0)` 后要再等一段（实测约 400ms+）再截图，否则截到滚动中间态
- 视觉核对必须降采样分块 + 逐项问答，直接问"该项 PASS/FAIL"，防止模型糊弄；截图后先做像素方差检查，全同=截图失败
- 修复部署被额度/权限阻塞时：先备份、留本地修改、如实呈报，不绕路、不硬来

## 验收标准
- 三视口 × 全部页面：无横向滚动、无遮挡、无错位，控制台 0 错误
- 每个 FAIL 有截图 + 根因 + 修复 + 复测记录，闭环后才算过
- 视觉核对结果有下属/多模态通道实测回报，总助不凭空断言
