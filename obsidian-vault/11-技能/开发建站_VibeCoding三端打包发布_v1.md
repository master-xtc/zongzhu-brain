# 技能：开发建站_VibeCoding三端打包发布_v1

## 技能名
VibeCoding 三端打包发布（安卓 APP / iOS APP / 微信小程序）全流程

## 用途
- 把 AI 编程（Vibe Coding，以 uni-app 为代表）做好的项目，从"能运行"走到"用户能用"：安卓真机调试→云打包 APK→应用市场发布；iOS 签名链路→云打包 IPA→App Store 上架；小程序上传→审核→发布
- 解决新手最痛的问题：三端先上哪个、要准备什么账号材料、签名/备案/审核资料有哪些坑
- 既可指导自己实操，也可作为给下属（WorkBuddy / Claude / Hermes）的三端发布任务说明书

## 触发场景
- 用 uni-app / AI 编程做好了 APP 或小程序，准备打包上架
- 不确定先上小程序 / 安卓 / iOS 哪一端
- 打包报错、审核被拒、证书/签名/备案资料不知道准备什么
- 需要把同一套代码分别发布到安卓市场、App Store、微信小程序

## 核心决策：三端先上哪一端（视频核心结论）
| 你的情况 | 优先选择 | 理由 |
|---|---|---|
| 快速验证想法，用户靠微信搜索/分享/扫码用 | 微信小程序 | 路径最短、传播最方便 |
| 用户主要在安卓手机，需要桌面入口/消息推送/系统能力 | 安卓 APP | 但注意：国内安卓不是统一商店（华为/小米/荣耀/应用宝各有账号和审核） |
| 覆盖苹果用户 | iOS APP | 只有 App Store 官方渠道，规则统一，但开发者会员/证书/审核更严格 |
- 新手建议：先小程序验证产品 → 再按真实用户设备补安卓和 iOS；第一次发布不要三端同时冲
- 三端本质区别：不是界面，而是「分发渠道 / 更新方式 / 支付规则 / 合规备案」

## 上架前必准备的六样东西（先备齐再动手）
1. 应用名称 + Android 包名 + iOS Bundle ID：长期身份，发布后不可随意更换
2. 安卓发布证书 + 证书别名 + 密码：证书丢失后更新非常麻烦，必须本地归档
3. 账号主体认证与备案：不同市场/服务类目/业务功能要求的资质不同，以各平台后台要求为准
4. 隐私政策 + 权限说明 + 第三方 SDK 信息：不申请业务用不到的权限
5. 应用图标（各平台尺寸规范）
6. 长期有效的审核测试账号：保证审核期间服务器与核心功能可访问

## 安卓流程（真机调试 → 云打包 APK → 应用市场发布）
1. 真机调试（先确认功能再打包）：HBuilderX 入口文件 → 运行 → USB 连手机 → 运行到 Android App → 自动装 HBuilderX 调试基座（失败重跑）→ 手机开开发者选项+USB 调试 → 真机窗口实测核心交互（登录/发帖/点赞）
2. 云打包：发行菜单 → 原生App-云打包 → 填应用包名（反向域名唯一格式，可让 AI 建议）+ 签名证书/别名/密码 → 提交云端队列，约 2-5 分钟出 APK
3. 发布（以华为应用市场为例，其他市场逻辑一致）：华为开发者联盟注册认证 → 创建应用（名称/分类）→ 填简介（说清用途）+ 图标/截图/隐私政策 → 软件版本管理 → 上传 APK（平台自动读取包名版本）→ **包名必须与 APK 完全一致** → 保存版本提交审核 → 约 1-3 个工作日通过

## iOS 流程（签名链路顺序是核心）
1. 签名链路顺序（背熟）：AppID 确定身份 → 发布证书证明开发者身份 → 描述文件把应用和证书绑定 → 最后签名生成 IPA
2. 准备：Apple Developer 付费账号 + 会员订阅；2026 年上传新构建需满足 Apple 当前 SDK 要求（HBuilderX 云打包前先升级对应版本）
3. 证书：钥匙串生成 CSR → 后台「证书、标识符与描述文件」新建 iOS Distribution 发布证书 → 上传 CSR → 下载证书
4. 描述文件：新建 Provisioning Profile → 选 App Store 发布类型 → 绑对应 App ID → 绑发布证书 → 下载
5. P12：证书+私钥用 openssl 辅助命令生成 P12，记录证书密码；证书/描述文件/P12 放同一指定目录
6. 打包：HBuilderX 云打包页选 Bundle ID（与后台 AppID 一致）+ Profile + P12 + 密码 → 提交 → 下载 IPA
7. 上架：Windows 用上传工具+苹果 API 密钥（后台建密钥，存 Key ID/Issuer ID）→ 提交 IPA 到 App Store Connect → 等构建处理 → 填名称/介绍/推广信息 → 选构建版本 → 补图标/联系信息 → 提交审核（约 2 天）

## 小程序流程（上传 → 审核 → 发布）
1. HBuilderX 运行到微信开发者工具（自动打开）
2. Manifest 配置 APPID 必须用微信公众平台的真实 APPID（不是测试号）
3. 开发者工具实测 + 预览功能手机确认
4. 点上传 → 填版本号和备注 → 上传成功
5. 微信公众平台版本管理：刷新看到开发版本 → 提交审核 → 补提审信息 → 审核中（约 1-7 天）→ 审核通过点发布

## 三端易错清单（视频总结，审核被拒先查这里）
- 小程序：主体、服务类目、备案、隐私协议、测试账号；页面不留测试/占位内容
- 安卓：应用包名、发布签名、APP 备案、隐私政策、权限申请、SDK 合规；不同市场资质不同，不套用
- iOS：功能完整、审核账号可用、服务器在线、隐私信息与真实数据一致；有注册账号要支持账号删除；数字内容/虚拟商品要合规 IAP 规则
- 审核时间只作参考：受平台/应用类别/资料完整度/审核高峰影响，以后台实时状态为准

## 验收标准
- 明确决策了三端优先级，且六样材料（名称/包名/证书/备案/隐私/图标/测试账号）清单齐备
- 安卓：APK 可安装，包名唯一且与市场记录一致，签名证书已归档
- iOS：签名链路（AppID→证书→描述文件→P12→IPA）每一步有明确产物与本地路径
- 小程序：APPID 为真实值，审核页无占位内容
- 每一端只走一条主线：选定渠道跑通后再复制经验到另一端
