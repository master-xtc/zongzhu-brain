# 技能_开发建站_网站搬运到微信小程序_个人主体合规与差距矩阵

**技能名**：网站 → 微信小程序 搬运前置评估（个人主体版）
**触发场景**：习总要求把已有网页/网站"复刻/搬运/开发成小程序"，尤其是个人主体小程序。
**适用模型**：任何具备文件读写与网络请求能力的执行体（总助直连即可，无需下属）。
**来源**：2026-09-14 CET4 备考网站复刻评估实战。

## 一、三条必须先查死的硬规则（省掉整轮返工）

1. **个人主体小程序不支持 web-view**
   - 官方原文：「承载网页的容器。会自动铺满整个小程序页面，个人类型的小程序暂不支持使用。」
   - 含义：**任何"套壳"路线直接作废**，必须原生 WXML/WXSS 重写。
   - 取原文方法：`Invoke-WebRequest https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html` → 去标签 → 正则搜 `.{160}个人.{200}`。
2. **个人主体可选类目只有 9 个大类**：快递业与邮政 / 教育服务 / 交通服务 / 生活服务 / 餐饮服务 / 旅游服务 / **工具** / 商业服务 / 体育。
   - 「教育服务」个人主体**仅开放"教育信息展示"**，且官方明确「不支持提供教育视频播放/直播、课程产品销售等服务」。
   - 「工具」的二级类目全部无资质要求：记账 / 日历 / 天气 / 办公 / 图片处理 / 计算器 / 报价比价 / 信息查询 / 预约报名 / 健康管理 / 备忘录。
   - **学习类工具走「工具-办公」或「工具-信息查询」**，对外口径写"辅助工具/查询工具"，禁用"培训/课程/教学/官方/最/第一"。
3. **个人主体不支持微信支付**，且新小程序需独立 ICP 备案。

## 二、标准步骤

1. **摸清源站**：列出页面清单（`data-page` / 页面 id）、功能点、数据量与数据结构（顶层数组名）。
2. **统计浏览器专有 API 用量**（决定改造难度，一条命令出结果）：
   ```powershell
   foreach($k in 'speechSynthesis','localStorage','setInterval','Blob','FileReader','document.querySelectorAll','addEventListener','AudioContext','requestAnimationFrame'){
     "{0,-28} {1}" -f $k, ([regex]::Matches($src,[regex]::Escape($k))).Count
   }
   ```
   - 无 Canvas / WebGL / AudioContext / rAF → 难度可控；
   - `speechSynthesis` 大量使用 → 触发 TTS 专项（见下）。
3. **逐项出差距矩阵**：模块 → 功能点 → 网页实现 → 小程序方案 → 差距类型 → 工时。
   差距类型四分类：`直接迁移` / `需改写` / `需替代` / `降级（或变易）`。
4. **API 替换对照表**（通用）：
   - `localStorage` → `wx.setStorageSync` / `getStorageSync`（key 结构可原样复用）
   - `querySelectorAll` + DOM 操作 → `setData` + 数据驱动渲染（工作量最大项）
   - `addEventListener` → `bindtap` / `bindinput` / `bindchange`
   - `prompt()` / `alert()` → `wx.showModal` + 自建输入弹层
   - `Blob` + `URL.createObjectURL` → `wx.getFileSystemManager().writeFile`
   - `FileReader` → `wx.chooseMessageFile` + `readFile`
   - SVG data URI 图标 → **光栅化本地 PNG**（小程序对 data URI 支持不可靠）
   - emoji 徽章 → 内联 SVG 或本地 PNG
   - `setInterval` 计时 → 保留，但息屏/后台会挂起，改用"记录开始时间戳 + 恢复补算"
5. **体积测算**：数据 + 逻辑 + 资源，对照主包 2048 KB 上限，判断是否需要分包。
6. **TTS 专项**（若源站用了 `speechSynthesis`）——四方案按序验证：
   | 序 | 方案 | 说明 |
   |---|---|---|
   | A | 微信同声传译插件 | 首选，0 元免服务器，**但个人主体可加载性需先验证** |
   | B | 后端 TTS | 需服务器 + 域名 + 备案，周期长，不推荐 |
   | C | 预生成音频包 | 离线可用，但体积大（814 词约 10–30 MB），需 CDN/分包 |
   | D | 降级 | 音标 + 跟读计时，零风险，兜底 |
7. **数据层迁移**：源站数据文件为唯一真相 → 写幂等转换脚本生成小程序模块 → 小程序端文件标「自动生成，勿手改」。

## 三、验收标准

- 差距矩阵覆盖全部页面与功能点，每项都有工时与差距类型，无"待定"；
- 明确给出：可否 web-view、类目建议、TTS 方案、分包结论、总工时、风险预案；
- 矩阵可直接当复刻阶段的验收清单（逐项打勾）；
- 数据量与 id 连续性（试卷 1–N、听力 1–N）在两端口径一致。

## 四、踩坑记录

- **别凭印象答"能不能上 GitHub"**：本机开代理时主观感受能上，`-NoProxy` 实测 `github.com` / `raw.githubusercontent.com` 均超时。凡网络可达性判断一律实测直连。
- **GitHub 定位**：源码仓库 + CI 触发器，**不是托管**；国内交付必须国内节点（腾讯云 COS / CloudBase，免备案当天可用）。
- **模型/插件能力先验证再排期**：TTS 插件能否用于个人主体未验证前，不要把它写进关键路径承诺。
- **单一数据源**：网页与小程序共用一份数据，禁止两端各自维护（FITCOMMAND 的 `trainData.js 勿手改` 教训）。
