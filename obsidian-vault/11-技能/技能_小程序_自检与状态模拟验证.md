# 技能_小程序_自检与状态模拟验证

**触发场景**：改完微信小程序页面后，需在**不打开微信开发者工具**的前提下确认“分支逻辑真跑通、标签真配对、文案真无敏感词”。

## 步骤
1. **JS 语法**：`node --check <每个改动的 .js>`（含 app.js，防连带语法错）。
2. **JSON 合法性**：`JSON.parse(fs.readFileSync(路径))` 校验 app.json / sitemap.json / project.config.json。
3. **WXML 配对**：用 `D:\接单客户\脚本_WXML标签配对稳健版_20260914.py`（正确处理多行属性、引号内 `>`、`{{ }}` 内 `>`、注释）。工程旧版 JS 检查器误报率高，勿直接用。
4. **WXSS 结构**：`{`/`}` 计数配平，并打印文件末尾 3 行确认闭合干净。
5. **敏感词**：`D:\接单客户\脚本_敏感词扫描_页面可见文案_20260914.py`；口径 = WXML 去注释去标签后的文本节点 + JS 去注释后的字符串字面量；`pages/`、`components/` 命中必须为 0。
6. **纯逻辑层单测**：node 里伪造 `wx.getStorageSync / setStorageSync / removeStorageSync`（内存 Map）后直接 `require` 工程的 `utils/*.js`，逐状态分支断言。
7. **页面状态模拟（关键）**：
   - `global.Page = cfg => captured = cfg`，`require(页面文件)` 拿到配置对象；
   - 实例化 `Object.assign({}, cfg)`，补 `data` 深拷贝与自写 `setData`（需支持 `'a.b'` 路径写法）；
   - `global.wx.getFileSystemManager = () => ({ readFileSync: p => fs.readFileSync(path.join(PROJ, p), 'utf8') })`，让 `utils/data.js` 真读 `data/*.json`；
   - `global.getApp = () => ({ globalData: {...} })`；
   - 依次调 `onLoad / onShow / 业务方法`，断言 `data` 结果。

## 验收标准
- 语法 / JSON / 配对 / 结构 / 敏感词五项全绿；
- 单测与状态模拟均 `FAIL 0`，且覆盖每个 UI 分支（如三态：未打卡 / 已打卡 / 断签）；
- 报告能列出每个状态的实际 data 取值，而非“看起来没问题”。

## 注意事项
- 纯 node + Python，零第三方依赖，无模型依赖。
- **校准原则**：检查脚本报错时，先拿未改动文件跑一遍——未改动文件也报错，就是工具的问题，不是代码的问题。
- 多行文件替换一律用 Python（幂等 + 命中数断言），不用 PowerShell（嵌套数组传参会展平）。
