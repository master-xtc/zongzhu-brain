# 排障_上下文健康管理（技能沉淀 · 2026-08-19）

## 技能名
排障_上下文健康管理

## 触发场景
- Codex 报 "maximum context length" / 上下文超限 / 会话历史过长；
- 会话跨多天、堆叠截图 base64、单会话文件 >10MB；
- 习总要求"继续对话/清理会话/提醒上下文"。

## 步骤
1. 定位超限会话：扫描 C:\Users\XTC\.codex\sessions\，按大小倒序找 >10MB 的 .jsonl，看 LastWriteTime 确认最近会话。
2. 确认任务与进度：读会话 jsonl 开头（首条 user 消息=任务起点）与结尾（最后 user 消息=当前任务）；产出目录按 cwd + 最近修改时间核对。
3. 生成交接文件：`交接指令_<任务名>续作_YYYYMMDD.md`，必备八要素——任务目标/项目位置/当前进度/接续步骤/验收标准/红线/新会话开场提示词/教训。
4. 提示习总操作：新建对话 → 粘贴开场提示词；旧会话不再发消息。
5. 归档清理：核对关键产出已落盘 → 超限会话 jsonl 移入归档目录（保留 30 天）→ 每周日汇总清理报告。

## 验收标准
- 新会话 5 分钟内恢复上下文并继续任务；
- 交接文件含全部八要素，新会话可独立读取；
- 旧会话已不再被使用（提醒到位）。

## 工具要点
- 被 Codex 占用的会话文件：用 FileStream(Open, Read, FileShare.ReadWrite) + StreamReader 读，勿用 OpenRead（会锁冲突）。
- 解析 jsonl：逐行 ConvertFrom-Json，payload.type=="message" 且 role=="user" 提取 input_text；跳过 >20000 字符的行（多为 base64）。
- 数据源：sessions jsonl、团队共享记忆、growth\reviews、交接文件。

## 适用模型
- Codex（总助）主执行；Claude/Hermes 值班会话同规则。

## 图片 base64 专项（2026-08-19 补充）
- 触发：会话里出现 data:image/base64、>50KB 的超长行、图片质检任务。
- 检测：读会话 jsonl，统计含 base64 的行数与总字节；>2MB 即高危。
- 处置：立即停用该会话（历史无法裁剪）；图片全部改用压缩 JPG + 文件路径方式；分批（≤3 张/轮）+ 结论落盘 + 开新会话。
- 替代链路：Hermes MCP read_image（按需读图不占历史）> subagent 读压缩小图 > 任何"贴原图进会话"。
