# 技能｜Word 长文档（docx）脚本化生成、自动分页与 COM 渲染排障

- 技能名：文档生产_docx长手册生成与Word渲染排障
- 版本：v2（2026-09-21 增补自动分页、目录域、COM 样式覆盖三节）
- 适用模型：Codex（总助）/ Claude / WorkBuddy 均可执行
- 来源任务：20260921_市调大赛参赛手册

---

## 一、触发场景

1. 需要产出 **多章节、多表格、20 页以上**的正式 Word 交付物（参赛手册、项目方案、报价书、操作规范）。
2. 需要把 Word **导出成 PDF 或页图**做视觉验收。
3. 出现"Word 渲染卡死 / CPU 空转 / 无产出"，或"文档出现整页空白 / 尾页只剩一两行"的排障场景。

## 二、前置检查

- Python 解释器：本机为 `D:\XTC\python.exe`（不是系统 python，务必用绝对路径）。
- 依赖：`python-docx`（生成）、`PyMuPDF`（转页图与几何核验）。
- 数据落盘一律 D 盘，窗口产出存窗口主目录，团队公共库（growth / 提示词库）例外。

## 三、步骤

### A. 生成 docx

1. **先定结构再写代码**：把一级章节、二级标题、表格清单列成大纲，确认章节数再动手，避免中途大改脚本。
2. **脚本单文件化**：一份脚本从头生成整份文档，不做多文件拆段拼接（拆段拼接会让后续 patch 极易踩引号/缩进坑）。
3. **中文字体**：`run.font.name` 设置后必须再设 `run._element.rPr.rFonts.set(qn('w:eastAsia'), '黑体')`，否则中文回退默认字体。
4. **表格着色**：金色表头 `#C9A96A`、深色底 `#0A0A0F`；表头单元格统一 `shading` + 白字/深字加粗。
5. **页码域**：用 `PAGE` 域插入，不要写死数字。
6. **每次改脚本后立刻 `py_compile`**，再运行生成。

### B. 自动分页：解决"整页空白"与"尾页只剩一行"

7. **不要用 `doc.add_page_break()` 做章前分页**。它是一段独立的空分页符，当上一章内容刚好排到页底时，会凭空多出一整页空白。正确做法：给章标题段落设 `paragraph_format.page_break_before = True`（本手册用 `heading(..., new_page=True)` 参数封装）。
8. **不要给标题设 `keep_with_next`**。它会把"标题 + 紧随段落"整块推到下一页，既抵消行距压缩的收益，又容易造出空白页。标题孤行问题用 `page_break_before` 与版面密度解决更稳。
9. **删掉紧邻标题的空段**。`make_table()` / `callout()` 常会在末尾补一个 `para(doc, "", size=6)` 作为间隔；当上一张表刚好占满一页时，这个空段会被挤到下一页，再叠加标题的 `page_break_before`，就产生一页只剩空段的空白页。生成后统一扫一遍 body，删除"空段落 + 紧随 Heading"的组合。
10. **尾页只剩一两行时，定点收缩而不是全局重压**。全局改行距会让所有分页位置漂移，经常把 A 页的孤行变成 B 页的孤行（打地鼠）。有效手法：在出问题的那一章内部删减约 40 个汉字（一行），或把该章某张表的单元格文案压到少一行。目标只有一个：把溢出的一行收回上一页。
11. **版面密度的合理档位**（中文 10.5pt 正文、A4）：正文行距 1.18–1.25、段后 4–6pt、一级标题段前 11–13pt、表格内行距 1.1、单元格上下内边距 36–50 twips、表格单元格段前段后 0–1pt。低于这个区间会显拥挤，高于会明显拉长页数。

### C. 目录页（TOC 域）

12. **用真域，不要手写页码**：插入 `TOC \o "1-2" \h \z \u` 域，再让 Word 更新，页码才会跟着内容自动变。
13. **样式名是小写**：python-docx 默认模板里目录样式内部名为 `toc 1` / `toc 2`，不是 `TOC 1`。用大写名查会抛 `KeyError`，若外面套了 `except KeyError: continue` 会被静默吞掉，表现为"改了但没生效"。
14. **不要在 docx 里改目录样式就指望生效**：Word 更新目录域并保存时，会把目录样式上手工加的 `rPr` / `pPr` 剥掉。可靠做法是在 COM 里改：遍历 `$d.Styles`，匹配 `NameLocal` 以 `TOC` 开头，直接设 `Font.Size` / `ParagraphFormat`，再第二次更新目录域。
15. **更新目录域的调用顺序**：`TablesOfContents.Item(1).Update()` → 改样式 → 再 `Update()` → `Fields.Update()` → `Repaginate()` → `Save()` → `SaveAs2(pdf, 17)`。顺序颠倒会导致目录仍按旧样式排版。

### D. 表格宽度与提示框对齐

16. **表格总宽必须等于版心宽**：A4（21cm）减去左右边距（2.6 + 2.6）＝ 15.8cm。所有 `widths=[...]` 求和必须等于 15.8，否则表格要么缩进要么越界。改文案时最容易漏改这一项，建议在脚本里加一行断言或事后用正则把所有 `widths=[...]` 求和扫一遍。
17. **单格提示框（callout）要设 `t.alignment = WD_TABLE_ALIGNMENT.CENTER`**。左对齐的单格表，Word 会把边框画在版心左侧约一个单元格左边距（约 7pt）的位置，肉眼看到"左边凸、右边短"。居中对齐后边框正好落在版心内。多列表格同样建议统一设居中。

### E. 导出 PDF / 页图

18. **用 SaveAs2 而非 ExportAsFixedFormat**：`$d.SaveAs2($pdf, 17)` 更稳定。
19. **后台启动 + 看门狗**：`Start-Process powershell -WindowStyle Hidden` 起后台任务；主流程轮询完成标记文件，超时则 `Stop-Process -Name WINWORD -Force`。完成后同步写一个 `.done` 标记文件，供脚本判定。
20. **注意"标记文件残留"竞态**：主流程若在后台脚本删除旧标记之前就检查标记，会立刻误报成功（耗时 0.0s）。判定前先由主流程自己删掉标记，或校验 PDF 的 `LastWriteTime`。
21. **转页图**：PyMuPDF 按 105dpi 渲染每页 PNG，落 `_qa\页图_vN\page_XX.png`。

### F. 排障：Word 卡死

22. **症状**：CPU 空转、进程不退出、无文件产出、500 秒以上无响应。
23. **根因（本机实证）**：多个进程/子代理并发拉起 Word 实例抢占，前台渲染被饿死。
24. **处理顺序**：`Stop-Process -Name WINWORD -Force` 清场 → 确认无并发调用 → 改 SaveAs2 + 后台 + 看门狗 → 重跑。
25. **预防**：渲染阶段禁止并发；同一时刻只允许一个 Word COM 调用。

## 四、验收标准

- **几何核验脚本**（可替代一部分目视）：逐页算正文块的内容顶端/底端与填充率、所有图形（表格边框）的左右边界。判定阈值：图形左边界 73.7pt、右边界 523.3pt（A4 + 2.6cm 边距）；填充率低于 20% 视为异常页；正文块数为 0 视为空白页。
- **注意几何核验的坑**：`page.get_text("blocks")` 会把页眉/页脚也算成块，必须先按文本内容剔除，否则会把"空白页"误判成有内容，或把有内容的页判成空白。
- **视觉核对**：**必须派具备视觉能力的下属逐页看图**，回报"page_XX：OK / 问题描述"，总助不得自行断言版面结果。几何核验与视觉核对是两条独立轨，都要过。
- 结构核验通过：章节数、表格数、正文字符数符合预期；关键词命中率 ≥ 90%；无 `{占位符}` / `TODO` / `XXX`；无隐私泄露（真实姓名、手机号、身份证）。
- 页图页数 = PDF 页数 = 文档预期页数。

| 现象 | 根因 | 解法 |

## 六、补充：目录（TOC）页数与行高控制（2026-09-21 v4 实战补录）

### 问题现象

给 `toc 1` / `toc 2` 样式设了字号与行距，导出后目录仍按 ~25pt 行高排版，65 条目录条目撑成 3 页、末页只剩 5 条。压缩行距后末页反而只剩 2 条（更难看）。

### 定位方法（关键）

不要靠猜。用 COM 直接问 Word"这段实际用了什么格式"：

```powershell
foreach ($p in $d.Paragraphs) {
  $sn = [string]$p.Style.NameLocal
  if ($sn -like "TOC*") {
    "{0} font={1} lineRule={2} line={3} before={4} after={5}" -f `
      $sn, $p.Range.Font.Size, $p.Format.LineSpacingRule, $p.Format.LineSpacing,
      $p.Format.SpaceBefore, $p.Format.SpaceAfter
  }
}
```

实测结果：`TOC 1` 段落已吃到设置（lineRule=4 固定值、line=13pt、after=0），**`TOC 2` 段落没有**（lineRule=5 倍数、line=14.2、after=4，即仍然继承 Normal）。也就是说"样式设了但只有一个层级生效"，此前用页面几何反推是查不出来的。

### 可靠解法：样式层 + 段落层双保险

```powershell
# 1) 先更新一次目录域，生成条目
$d.TablesOfContents.Item(1).Update()

# 2) 样式层：用 -like "TOC*" 匹配，不要用 -eq "TOC 1" / -eq "TOC 2"
foreach ($st in $d.Styles) {
  $n = [string]$st.NameLocal
  if ($n -like "TOC*") {
    $st.Font.Size = 10
    $st.ParagraphFormat.SpaceBefore = 0
    $st.ParagraphFormat.SpaceAfter = 0
    $st.ParagraphFormat.LineSpacingRule = 4   # wdLineSpaceExactly
    $st.ParagraphFormat.LineSpacing = 15
  }
}

# 3) 段落层：本次渲染立即生效（更新目录域会重置直接格式，所以必须放在 Update 之后）
foreach ($p in $d.Paragraphs) {
  $sn = [string]$p.Style.NameLocal
  if ($sn -like "TOC*") {
    $p.Format.SpaceBefore = 0; $p.Format.SpaceAfter = 0
    $p.Format.LineSpacingRule = 4; $p.Format.LineSpacing = 15
    $p.Range.Font.Size = 10
  }
}

# 4) 之后不要再调用 TablesOfContents.Update()，否则直接格式会被冲掉
$d.Fields.Update(); $d.Repaginate(); $d.Save(); $d.SaveAs2($pdf, 17)
```

### 目录页数怎么定档（A4、版心 727pt 高）

- 条目数 N × 单条行高 ≈ 目录总高；超过 727pt 就多一页。
- **不要追求"刚好压进一页"**：压到 730–760pt 这种临界值，会多出一页只有 2–5 条的尾页，比 2 页更难看。
- 正确做法是**主动选档**：让总高落在 950–1100pt，目录稳定占 2 页、第二页约 40%–50% 填充，视觉上正常。本手册取 `TOC 1 = 16pt`、`TOC 2 = 15pt`，65 条 → 2 页、次页 46%。
- 如果条目太多（>90 条），考虑把附录子标题降为三级标题（不进目录），或把目录做成两栏无框表格。

### 页码正确性怎么验

目录域更新与导出在同一次 COM 会话内完成，页码必然一致；但**改版后必须抽查**：从目录文本里正则提取"标题 …… 页码"，再在 PDF 里按首行匹配同标题所在页，逐条比对。本手册抽查 6 条（章节、附录、附录子节）全部一致。

## 七、单份 5—10 页"申报/材料类"文档专项（2026-10-12 实战补录）

来源任务：2503302班 优良学风班级申报《班级简介》（6 页，封面＋目录域＋6 章＋3 表＋1 图）。

### A. 这类文档的额外硬要求

1. **目录**：不少学校明确要求"申报材料前面加目录"。本类文档一律：封面 → 目录（`TOC \o "1-2" \h \z \u` 真域）→ 正文。条目少（≤10 条）时目录自然只占 1 页，填充率 25% 左右是正常的，不要去"压行距"凑版面。
2. **数据必须可溯源**：把数据来源写在表下，格式"数据来源：学校教务系统《XX表》、学院《XX汇总表》"。评审要能按图索骥核对。
3. **主动公开不利数据**：例如把"不及格 37 门次（占 5.56%）"和"及格率 94.44%"并列写。评审本来就要求学生交成绩单、能自己算出来；藏反而掉分。
4. **正面回应评审关注点**：通知里点名的指标（如及格率、违纪率）必须有对应句子，不要让评审自己去找。
5. **荣誉单独成表**：校级奖学金人数及等次、三好学生、优秀学生干部＝最硬的证据，配"说明"列写认定依据。
6. **隐私脱敏**：班级集体材料里列同学姓名很常见，但总则红线优先——一律不写姓名，只留汇总数据。检查脚本：把全班名单逐个 `in` 一遍正文＋表格文本，命中即为泄露。
7. **声明式表述要标注待确认**：凡属班级自述（"无违纪""无异议"）而非台账支撑的句子，交付时必须单独列出来请习总核实，不得默认属实。

### B. 目录域页码的快速回读验证（比几何反推快 10 倍）

Word COM 更新目录域并保存后，**直接用 python-docx 回读目录段落文本**即可确认页码：

```python
from docx import Document
d = Document(path)
for p in d.paragraphs:
    if "\t" in p.text and len(p.text) < 60:
        print(repr(p.text))     # 例：'四、互助共进：不让一个同学掉队\t5'
```

只要"目录里的页码 == 该标题实际所在页"，目录就不会错。本任务回读得 3/3/3/5/5/6/6，与 PDF 实际页完全一致。

### C. 页尾段落被拆断的修法

表下的"数据来源"或解读段若跨页断成两半（上一页留半句），给该段设 `paragraph_format.keep_together = True`（Word 的"段中不分页"），整段会被推到下一页，页面观感立刻干净。注意：这与"标题不要设 keep_with_next"不冲突——**正文段可以 keep_together，标题段不要 keep_with_next**。

### D. 中文标点悬挂不是越界（重要，别误判）

几何核验发现正文行 `x1 = 533.7pt` 超出 A4＋2.6cm 边距的版心右界 521.6pt，看着像越界 **12.1pt**。逐 span 定位后确认：这些行**都以中文逗号结尾**，超出量正好等于一个 12pt 全角字宽——这是 Word 中文版式默认的"**允许标点溢出边界**"，属正常排版，**不是缺陷**。

- 判据：`超界量 ≈ 正文字号`且`行末为中文标点` → 标点悬挂，放行。
- 反之：`超界量 ≠ 字号` 或行末为非标点字符 → 真越界，必须查。

### E. 视觉下属派工的红线（本任务踩坑，血泪）

**现象**：把整页 PNG 派给视觉子代理，连续三次报"超过最大上下文 1048576"：6 张 130dpi 整页图 → 请求 **1,315,798** token；3 张共 286KB → **1,057,694**；**单张 117KB → 1,076,704**。

**根因**：图片 token 消耗**不是按字节线性增长**；且子代理会随父会话历史增长而不断抬高基线（同尺寸图片，会话早期能过、后期过不了）。**单一子代理单批里塞多张整页图 = 必炸**。

**可用档位（实测）**：

| 项 | 安全值 | 说明 |
|---|---|---|
| 单批图片数 | ≤ 3 张（首选 1—2 张/批） | 超过就分批派 |
| 单张宽度 | 780—860px | 再宽收益低、风险陡增 |
| JPEG 质量 | 62—72 | 文字仍清晰可读 |
| 单张体积 | ≤ 120KB | — |
| 单批总体积 | ≤ 180KB | 实测 177KB 通过、286KB 崩 |

**标准动作**：① 先 `Pillow` 生成 860px/q68 缩略图；② 按页或按 2 页切批；③ 分批派多个子代理；④ 一旦出现"超过最大上下文"就**立即停止加图重试**——那不是尺寸问题，是基线已顶格，只能**落盘＋开新会话**再做剩余页的视觉验收。

**兜底轨**：视觉下属被上下文卡住时，用"确定性轨"顶上——python-docx 回读判内容、PyMuPDF 判几何（版心边界/填充率/图片 bbox 与居中）、rapidocr 判页码与大致版式；三条中至少两条通过才可交付，并在汇报里**如实写明哪些页没做视觉核对**。

### F. OCR 只能当辅助

本任务 rapidocr 漏读了表2"人数"列全部数字（2/7/11/4/5/29），把"疏导"读成"疏蔬导"，还打乱了表格列序。**若只凭 OCR 判断，会把合格文档误判为有缺陷**。OCR 用于判页码、判大致版式、做大范围粗筛；**内容正确性一律以 python-docx 回读为准**。
