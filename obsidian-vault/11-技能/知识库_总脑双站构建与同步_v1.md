# 技能：知识库_总脑双站构建与同步

## 触发场景
需要更新总助大脑（新增知识/能力/复盘）并同时刷新旧完整站与加密共享站时使用。

## 前置检查
1. 确认源目录：`D:\小说文件\总助大脑`（data 为数据层，_build 为构建层，_deploy 为发布层）。
2. 确认发布远端与线上地址，`git -C _deploy remote -v`、`git status`。
3. 确认共享站构建根与一键脚本路径存在，密码文件可读。

## 步骤
1. 写数据：新条目写 `data\manual.json`（id/name/title/domain/detail/tools/status/created_at 字段齐全）。
2. 去重：与静态条目同义的 manual 条目删除，避免同一知识两份 id。
3. 构建：依次执行 collect.py → build_kb.py → generate_md.py → inject.py → export_obsidian.py。
4. 自检：`meta.counts` 各项之和等于 total；manual 条目 id 全部出现在 knowledge 与 graph.nodes；graph 无重复 id；版本号三处一致（meta、页脚、README）。
5. 发布旧站：复制 knowledge.json/knowledge.md/manual.json/灵感备案.json/index.html/obsidian-vault(.zip) 到 _deploy，git add/commit/push。
6. 发布共享站：运行 `更新总脑共享版_一键同步.ps1`，确认只产出加密载荷。
7. 线上验收：查 Pages 最新构建状态；抓取线上页面检索最新条目标题；用密码解密共享站抽查。

## 验收标准
- 线上页面出现本次新增条目标题与最新版本号。
- 知识图谱节点数与 JSON 一致，新增 cap/kno 节点可见。
- 共享站无明文知识泄漏，密码文件与备份一致。
- 旧站与共享站构建日期、条目数一致。

## 适用模型
Codex（总助）本机执行；共享站加密步骤需 Node 环境。

## 踩坑记录
- manual 合并在 graph 构建之后 → 图谱漏条目，必须在合并后补点。
- 重建覆盖 knowledge.json 会丢 changelog → 重建前先读旧文件保留。
- 硬编码统计数字（54/22/115）会腐烂 → 全部动态计算。
