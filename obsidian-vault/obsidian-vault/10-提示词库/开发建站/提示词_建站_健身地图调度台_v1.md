# 提示词_建站_健身地图调度台_v1

## 名称
健身品牌地图调度台（私教上门版）建站提示词

## 用途
让编程 AI（Codex/Claude/任意）生成"真实地图 + 教练/学员/路线调度"的单页功能页，与健身品牌叙事站风格统一；参照抖音"生鲜配送调度台"（百度地图 JS API 4.0）同款交互。

## 适用场景
- 健身品牌站新增"地图调度台"章节/独立页（场景B：私教上门）；
- 接单演示（同城配送/上门服务/物流可视化类客户项目）；
- 拍摄抖音同款"我用 Vibe Coding 做了XX调度台"引流内容。

## 变量位
- {门店}：门店/基地名称与地址；
- {教练}：教练姓名/方位/容量（人数、位置描述、每教练最大单数）；
- {学员订单}：学员姓名/地址/预约时间/课程（6-8 单示例数据）；
- {服务半径}：默认 6km；
- {品牌色}：默认 深空黑 #0A0A0F + 荧光绿 #D2FF00；
- {地图平台}：百度（JS API 4.0，BMap.*）/ 高德（JS API 2.0，AMap.*），Key 由用户提供。

## 正文模板
```
请为我的健身品牌网站做一个"地图调度台"功能页面。开工前先查库：读取本提示词条目，按其中要求执行。

【背景】健身品牌单页网站（深空黑#0A0A0F + 荧光绿#D2FF00 运动风，移动端优先），新增真实地图能力页面。

【目标】单页 HTML+JS 地图调度台（私教上门场景B），移动端优先，视觉与主站一致。

【业务数据（示例可替换）】
- 门店：{门店}；
- 私教 {人数} 人：{教练列表}，每人最多 {容量} 单；
- 学员预约 {N} 单：{姓名/地址/预约时间/课程}；
- 服务范围：门店 {服务半径}，超范围学员标记"超范围·不上门"。

【功能清单（视频同款）】
1 真实地图展示（用我提供的地图 Key）；
2 覆盖物：门店 Marker+Icon+Label、教练 Marker、学员订单 Marker、服务范围 Circle、路线 Polyline；
3 地址解析：学员地址 Geocoder 转坐标，超范围自动拦截提示；
4 派单：点"派单"按"最近教练优先+预约时间排序"自动分配，进度提示"正在计算XX的路线成本（x/n）"；
5 路线规划：DrivingRoute 生成"教练当前位置→门店→学员1→学员2"真实道路路线，右侧面板显示总里程/预计用时/迟到风险；
6 专注模式：点教练只显示该教练及其学员路线；点路线站点地图高亮对应路段；
7 路线策略：默认推荐/避开拥堵/避开高速对比切换（MVP 可只做默认推荐）。

【视觉规格】深空黑底+荧光绿点缀；英文点缀字（PULSE DISPATCH / LIVE CLASSES）；卡片信息清晰；无 emoji、无花哨装饰、无低质占位图。

【技术验收】移动端 390px 无横向滚动；地图不黑屏；Key 做可替换配置（顶部注释）；超范围拦截/派单分配/路线显示三项可正常演示；无死链；风格与主站一致。

【交付要求】站点存 D 盘（建议 D:\健身网站\map-dispatch\），文件一看即知（index.html + data.js + config.js）；附《调度台_说明与待办.md》；完成后按团队沉淀机制回填（reviews + 提示词库）。
```

## 变体
- 场景A（展示型）：砍掉派单/路线/教练，只留 门店 Marker + 服务范围 Circle + 点击弹窗 + "点我导航"链接，半天可交付，作为主站"找到我们"章节。
- 换行业：生鲜配送（中心仓/骑手/订单）、同城跑腿、宠物上门、维修上门——业务数据与角色名替换即可，结构不动。

## 验收标准
- 三项核心交互（超范围拦截/派单分配/路线显示）演示可跑通；
- 移动端不溢出、地图不黑屏、Key 可替换、风格与主站一致；
- 交付含说明文档与待办清单；无 emoji/死链/低质占位。
