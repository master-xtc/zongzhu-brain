# 提示词 · 记忆：关键产出立即落盘 + 分阶段开新会话（工作节奏铁律）

> 归属：调度指令 / 工作纪律
> 版本：v1.0 · 2026-08-15
> 触发词：上下文超限、开新会话、交接、落盘、保存产出、阶段汇报

## 基本信息
- 名称：记忆_关键产出立即落盘与分阶段新会话
- 用途：把「关键产出立即落盘 + 每完成一个阶段开新会话」固化为总助（Codex）的默认工作节奏；任何会话开场自动遵守，防上下文超限、让会话更聚焦。
- 适用场景：一切 Codex 会话，尤其是长任务（建站、方案、写书、多阶段交付）；任务预计超过 1 个阶段或产出多个文件时强制启用。
- 版本/日期：v1.0 / 2026-08-15
- 背景教训：BIM 任务会话曾请求 1,110,923 token，超过 1,048,576 上限报错；根因是历史过长（多次整段文本、截图 base64）。

## 变量位（使用时替换）
- {主目录}：当前会话窗口所属工作区根目录（本窗口 = D:\问题解决；规则：产出存主目录，团队公共库除外）
- {阶段}：调研 / 方案 / 实现 / 验证 / 交付（阶段边界 = 一次可独立验收的产出）
- {产出物}：方案定稿、代码实现、测试结果、排障结论、交付文档、优质提示词、复盘

## 正文模板（记忆档案内容，可直接存入 memories\ 或开场粘贴）

# 规则_关键产出立即落盘与分阶段新会话（2026-08-15 习总钦定）

## 一、适用
- 所有 Codex 会话；长任务（预计超过 2 个阶段或 30 分钟工作量）强制启用。

## 二、两条铁律
1. 关键产出立即落盘：任一阶段的方案、代码、文档、结论、优质提示词，完成即写入磁盘文件（D 盘主目录或团队公共库），不等任务结束、不等习总开口、不留在聊天记录里。
2. 每完成一个阶段开新会话：任务按阶段拆解，每阶段结束并落盘后，主动建议习总开新会话继续下一阶段，并附「新会话开场提示词」或交接说明；禁止一个会话硬扛完全程。

## 三、什么是「关键产出」（判定）
- 方案/设计定稿、代码实现、测试验证结果、排障结论、交付文档、优质提示词、复盘。
- 一句话：凡是「下次可能还要用/还要看」的内容 = 关键产出。

## 四、执行动作
1. 开工时先声明：本阶段预期产出 + 落盘路径（先想好放哪）。
2. 产出出现即写文件：本机 apply_patch 被 ACL 阻断时，用 PowerShell 写 UTF-8 无 BOM（[System.IO.File]::WriteAllText($p,$c,[Text.UTF8Encoding]::new($false))）；CRLF 文件先按 LF 处理锚点匹配，再回写 CRLF。
3. 命名公式：类别_对象_用途(_时间).扩展名；放窗口所属主目录（团队公共库 = growth\ + 提示词库 + 团队共享记忆 除外）。
4. 阶段完成汇报：做了什么 / 结果 / 遗留问题 + 落盘路径；给出下一步与是否开新会话的建议。

## 五、反例（禁止）
- 把大段文本或截图 base64 反复粘贴进聊天（BIM 任务曾因此触发上下文超限报错）。
- 产出只存在于对话流里不写文件，导致新会话无法恢复上下文。
- 一个会话硬扛全部阶段，等全部交付才落盘。

## 六、验收标准
- 每个阶段结束，都能报出明确文件路径，且该文件可被新会话独立读取。
- 新会话开场 5 分钟内恢复全部上下文（靠文件，不靠历史）。
- 会话 token 保持中型水位，不逼近上限。

## 七、示例
- 正例：BIM 升级任务 → 方案/代码/备份全部落盘 D:\问题解决 与 D:\BIM材料 → 另产出《新会话开场提示词》供续作会话使用。
- 反例：把整份 98KB index.html 贴进聊天让 AI 分析（占 8 万+ token），应只给路径。

2. 完整版（记忆档案）：见上方正文模板。

## 验收标准
- 新会话开场即自动声明落盘路径与阶段边界。
- 连续 3 个长任务无上下文超限、无「产出丢失」事件。
- 每次交付汇报都带落盘路径。
